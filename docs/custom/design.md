# 独自機能の設計

確認日: 2026-10-10。以下は実装案であり、動作確認済み機能の一覧ではありません。

## 要件と初期方針

確定した要件はWindowsホスト、複数OSのMoonlightクライアント、接続中に配信範囲を変更できることです。クリップボードの範囲は難易度と自動化できる範囲を見て選択します。

初期案は、既存Moonlightで受信できる動的矩形切り出しと、対応クライアント向けのテキスト双方向同期です。クリップボードの初期対応クライアントはMoonlight QtのWindows/Linux/macOS版を候補とします。Android/iOSの同期は別実装・別検証になります。

2026-10-10に[usm916/moonlight-qt](https://github.com/usm916/moonlight-qt/tree/custom/main)を別リポジトリ・別フォルダとして準備し、[usm916/moonlight-common-c](https://github.com/usm916/moonlight-common-c/tree/custom/main)を共有通信ライブラリの保存先として作成しました。ホストとクライアントは同じ固定コミットをsubmoduleで参照します。通信仕様の案と責務は共通ライブラリ内の[clipboard-v1.md](../../third-party/moonlight-common-c/docs/custom/clipboard-v1.md)へ集約します。依存構成の確認は`scripts/check-custom-pair.ps1`で行います。同期機能自体はまだ実装されていません。

| 機能 | 実装規模の見積もり | クライアント側の作業 | 自動化・検証の境界 |
| --- | --- | --- | --- |
| クライアントのテキストをホストへ入力 | 小 | Moonlight Qtに既存の貼り付けショートカットあり | 既存機能を確認。ホストのクリップボード自体を同期する機能とは異なる |
| テキスト双方向同期 | 中 | 対応するQtクライアントと共通ライブラリが必要 | パーサ・状態管理・Windows実装を自動テスト可能。各OSのコピー操作を実機確認 |
| テキストと画像の双方向同期 | 大 | 画像形式と大容量転送への対応が必要 | 容量制限・分割・帯域制御・各OS形式変換を追加。初期版の後に検討 |
| 接続中の矩形変更、固定配信サイズ | 中〜大 | 最初はホストWeb UIから操作。映像受信は既存Moonlightを使用 | 座標変換を単体テスト可能。GPU、DPI、入力、再接続は実機確認 |
| 配信サイズ自体の接続中変更 | 大 | デコーダとプロトコルの対応確認が必要 | 複数クライアントとの再設定を要検証。初期案では配信サイズを固定 |

これらは設計に基づく相対評価で、作業時間や全OSでの自動完了を保証するものではありません。

## 接続中の配信範囲変更

パイプラインは「画面取得 → 矩形切り出し → 固定サイズへ拡縮・余白追加 → エンコード → 配信」とします。映像の解像度とコーデックは接続時に確定し、範囲変更で再接続しない方式を第一案とします。

初期操作はSunshineの既存認証付きWeb UIに範囲の編集・適用・全画面へ戻す操作を追加する案です。配信画面内のショートカットやドラッグ操作は、後からクライアント側へ追加できます。

切り出しの設定は選択ディスプレイ内の物理ピクセルで`x, y, width, height`を指定します。最初は単一の有効配信セッションに限定し、複数接続時の独立した範囲管理は後続とします。

実装時に満たす条件:

- 矩形の正の幅・高さ、ディスプレイ境界、整数オーバーフローを検証する。
- 範囲外の入力はエラーとし、適用中の範囲を維持する。
- 描画と入力変換が同じ範囲・世代を参照する状態管理を設ける。
- 余白を除いた映像上の座標を切り出し矩形へ逆変換し、モニターのデスクトップ座標を加える。
- 相対マウスは用途に応じた倍率を定義し、絶対マウス・タッチ・ペンも検証する。
- カーソル、DPI、回転、負のモニター座標、HDRとSDRを扱う。
- 範囲変更時は余白を再描画し、古い映像領域が残らないようにする。
- GPU経路とCPU経路の適用可否を明示し、未対応経路で黙って全画面を配信しない。
- 停止・再接続・ディスプレイ変更時の範囲リセットまたは再検証を定義する。
- Web APIには既存の認証・CSRF保護を適用する。

主な接点は`src/platform/windows/display_vram.cpp`のGPU変換、`src/video.cpp`のソフトウェア変換と`make_port()`、`src/input.cpp`の入力座標変換、`src/confighttp.cpp`と`src_assets/common/assets/web/`の管理UIです。小さな範囲管理モジュールへ独自ロジックを寄せ、本流ファイルへの接続部分を限定します。これはソース調査に基づく候補で、実装前に各エンコーダ経路を確認します。

受け入れ条件は、接続を保ったまま範囲を変更できること、見えている位置をクリックできること、全画面へ復帰できること、範囲外の映像が残らないことです。

## クリップボード

取得したSunshine本流では、ストリーミング用クリップボード実装は見つかっていません。Web UIのログコピー機能とは別に実装が必要です。

再利用を検討する未マージの提案:

- [moonlight-common-c #155](https://github.com/moonlight-stream/moonlight-common-c/pull/155): テキスト送信とホストからの通知。
- [moonlight-qt #2019](https://github.com/moonlight-stream/moonlight-qt/pull/2019): 既定OFFの同期設定。Windows/macOSの実機検証はPR説明では未実施。
- [Sunshine #5782](https://github.com/LizardByte/Sunshine/pull/5782): Linux X11向けのDraft。Windowsのクリップボード処理は未実装で、レビュー上の指摘もあるため、そのまま製品実装として取り込まない。

既存Qtクライアントの[キーボード処理](https://github.com/moonlight-stream/moonlight-qt/blob/master/app/streaming/input/keyboard.cpp)には`Ctrl+Alt+Shift+V`によるテキスト入力があります。これは双方向のクリップボード同期とは異なります。

第一案は上記提案のプロトコルを確認し、共通処理を評価した上でWindowsのUnicodeクリップボードを実装することです。提案にある32,755バイト上限とメッセージ番号は、固定コミットのコードをレビューしてから採否を決めます。未マージの提案なので今後の仕様変更も想定します。

同期は利用者が有効化した接続に限り、方向別に制御します。UTF-8/UTF-16変換、空文字列の扱い、重複通知・反射ループ防止、クリップボードが他プロセスに占有された場合の再試行、終了時の購読解除を実装します。認証・暗号化された経路を使い、内容はログに記録しません。

WindowsサービスのSession 0からではなく、利用者のデスクトップで動くSunshineプロセスからクリップボードへアクセスする構成を確認します。初期は複数クライアントへの無条件共有を行わず、対象セッションを明確にします。

画像は後続候補です。フォーマット変換と転送上限、分割・キャンセル、映像を圧迫しない転送制御を設計してから追加します。Android/iOSはQt版とは別の対応と実機検証が必要です。

## 低帯域への対応

切り出しは同じビットレート設定のままで通信量が必ず減るものではありません。小さな領域の文字を低い配信解像度でも読めるようにし、ビットレート・FPSの削減と組み合わせる用途を想定します。

まず本流の`max_bitrate`と`minimum_fps_target`、Moonlight側の解像度・FPS・ビットレート設定を使って測定します。設定の意味は[本流の設定資料](../configuration.md)を参照します。FECと音声、通信ヘッダーも回線を消費するので、動画の設定値だけで総帯域を見積もりません。

自動ビットレート適応は、既存の計測とエンコーダの接続中再設定を確認する別機能として扱います。初期段階では、回線条件ごとの設定プリセットと測定を優先します。

比較条件を固定して、読める文字サイズ、総送信量、フレーム遅延、フレーム欠落、GPU使用率を記録します。静止した文章、スクロール、動画で評価し、通常回線と帯域・遅延・損失を制限した回線を比較します。

## 実装順序と検証

1. MSYS2 UCRT64の依存環境を準備し、未変更の本流をビルドして基準にする。
2. 範囲管理と入力変換の単体テストを作り、GPU経路へ接続する。
3. Web UIによる接続中変更を追加し、標準Moonlightで切り出しを検証する。
4. 低帯域設定と測定で、切り出しによる画質と通信量の効果を確認する。
5. 既存クリップボード提案をレビューし、WindowsホストとQtクライアントのテキスト同期を実装する。
6. Windows/Linux/macOSの実機で接続・コピー・再接続を確認し、画像やモバイル対応を再評価する。

GPUを使わない範囲検証・座標変換・パケット解析・状態遷移は自動テストに寄せます。GPUごとの映像、他OSのクリップボード、利用回線の体感品質は対応機器での検証が必要です。

本流更新の取り込みごとに、通常配信、切り出しOFF/ON、接続中変更、入力、クリップボードOFF/ON、非対応クライアント、切断・再接続を確認します。公開前に、ホスト・クライアント・共通ライブラリの固定コミットとテスト済みOS/GPUを記録します。
