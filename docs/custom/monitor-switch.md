# マウスの端中央でのマルチモニター切り替え

2026-10-17。クロップの初期値は上下左右20px。既存の0設定も20pxとして扱う。
モニター切り替えは独立したオン／オフ設定で、配布物の既定値はオフ。このPCでの試験用にはオンにする。

## 操作

Configuration → Audio/Video のクロップ設定で `Switch monitors at edge centers` をオン。
`Stationary wait` の既定値は600ms（100〜5000ms）。保存後にホスト再起動・Moonlight再接続で反映する。

```ini
viewport_crop = enabled
viewport_crop_monitor_switch = enabled
viewport_crop_monitor_switch_delay = 600
```

1. 通常のクロップは端20pxで隣の固定枠へ切り替える。
2. モニターの外端に達した枠で、上下左右いずれかの辺の中央にマウスを止める。
   対象は表示中の辺の中央20%・端から20px以内。隣接する方向に画面がなければ何もしない。
3. 600ms静止すると、その方向でマウスと同じ横／縦座標にある最寄りのモニターへ移る。
   4pxを超える動きで待ち時間を最初から数え直す。斜めだけの画面や座標の合わない隣画面へは飛ばない。
4. 切り替え成功後、マウスを移動先の入口から21px内側へ移し、新しい画面内のクロップ枠で操作を続ける。
   反対方向も同じ操作。画面間の空間・負座標・縦配置を扱う。

対象はWindowsのD3Dクロップ・**1つの有効な配信接続**・同じGPU・同じHDR状態。
複数接続では他クライアントを巻き込まないため自動切り替えを休止する。
直接タッチ／ペンを押している間も休止。テキストキャレットではなく実マウス位置で判定する。
モニター移動を有効にした場合だけ、既存の「選択画面以外を無効化」は「選択画面を有効化」へ読み替え、他画面を残す。
外部コマンドや既に無効な画面を自動で有効にする機能ではない。

## 接続と負荷

既存のキャプチャ／エンコーダー再初期化経路を使う。Sunshineプロセス、RTSP／UDPの接続、送信解像度は維持する。
映像は再初期化中に止まる可能性がある。移動先のキャプチャ初期化・GPU/HDR互換性・マウス移動に失敗した場合は元の画面へ戻す。
同じGPUでもリソース枯渇やデバイス消失でエンコーダー再作成が失敗する可能性は残るため、切断を完全に防ぐ保証ではない。

`Monitor edge dwell` ログは移動先・採用画面・成否・`capture_reopen_ms` を記録する。
この時間はキャプチャ再作成部分だけで、NVENC再作成・回線・クライアントの表示復帰までの総停止時間ではない。
マウスの確認は最大40Hz、画面配置の確認は最大2Hz。GPUでの画像差分計算や画像のCPU読み戻しは追加しない。

## 元へ戻す

- 同じバイナリーで止める: `Switch monitors at edge centers` をオフにして保存・再起動。クロップは20pxのまま。
- 機能追加前へ戻す: 作業フォルダー直下の `Rollback Monitor Switch.cmd` を実行。
  `cmake-build-custom/package-crop-margin-20` の全162ファイルと復元用スクリプトのハッシュを確認してから、
  専用サービスを停止し、20px単体版全体を配置・再起動する。共通設定とペアリングは維持する。
  旧20px版にはモニター切り替え機能がなく、新しい切り替え設定は使われない。
- 停止せず検証だけ: `Rollback Monitor Switch.cmd -CheckOnly`。

巻き戻し先exe SHA-256: `d71030946d2c98881323295cc14542aef46723f92c6cf9b00de32bbe1fa6a4ff`。
`checkpoint-crop20.json` が全ファイルと復元スクリプトを固定し、`checkpoint-crop20-source.zip` と別の一覧に機能追加前の変更済みソースを保存している。
ソースZIPは手動復旧用の記録。上記コマンドは稼働パッケージだけを戻し、作業中ソースを上書きしない。
AnyDesk、Moonlight Internet Hosting ToolのIPv6転送、両Sunshineサービスの起動方法は変更しない。
