# 要求解像度でのクロップ配信

Windowsホストの選択中の1モニターがクライアントの要求サイズより大きい場合、要求サイズの範囲を等倍で切り出す。
例: 3840×2160のデスクトップ → 1920×1080の配信。カスタム解像度も同じ経路を使う。
切り出し枠の移動でサーバーやエンコーダーを再起動しない。モニター横断はオプションの[端中央での静止切り替え](monitor-switch.md)で対応する。連続合成は未対応。

## 有効化

Web UI → Configuration → Audio/Video → Crop oversized desktop to client resolution をオン。
Left/right crop switch margin / Top/bottom crop switch margin は上下左右とも初期値20px。現在の表示範囲の端から20pxに入ると隣の固定枠へ切り替える。既存の viewport_crop_deadzone_width / height を使い、旧設定の0も20pxとして扱う。
設定を保存しホストを再起動、クライアントでFHDなどを選んで接続する。

```ini
viewport_crop = enabled
viewport_crop_deadzone_width = 20
viewport_crop_deadzone_height = 20
cursor_focus_follow_text = enabled
cursor_focus_mouse_move_threshold = 6
```

クロップ枠は連続移動せず、以下の固定位置に切り替える。横と縦を独立して計算する。

- 実サイズ S が見えるサイズ C より大きい辺では、区画数 N = floor(S / C) + 1。割り切れない場合は切り上げと同じ、割り切れる場合は1区画増やして重なりを作る。C = min(実サイズ, 要求サイズ)。収まる辺は1区画。1px等の退化サイズでは重複する原点を増やさないよう制限する。
- N が1なら原点は0。N が2以上なら区画 i の原点は floor(i × (S − C) / (N − 1))、i は0〜N−1。
- 3840→2560: 2区画、原点0・1280（左・右）。重なりは1280px。
- 3840→1280: 4区画、原点0・853・1706・2560。隣接枠には426〜427pxの重なり。
- 3840×2160→1280×960: 横4×縦3の12位置。縦の原点は0・600・1200。
- 3840×2160→1280×720: 横4×縦4の16位置。
- 割り切れない場合も両端に到達し、隣接する枠が重なって全体を覆う。

現在の表示範囲の上下左右20pxを切り替え帯とし、中央では枠を固定する。
1280×960なら、左x=0〜19、右x=1260〜1279、上y=0〜19、下y=940〜959が対象（表示内座標）。
隣の枠がないモニター外周では切り替えない。隣接枠の重なりが狭い場合だけ、
切り替え直後の往復を防ぐため各帯を重なりの半分以下に制限する（最小1px）。
大きなマウス移動・キャレット移動では複数区画を一度に移れる。アンカー不明時は現在位置を保つ。
初回は取得できるアンカーの区画、なければ実画面中央を含む区画を選ぶ。
文字入力中は取得できるキャレット、取得不可ならマウスへ戻る。クリックや閾値以上の移動でマウス中心に切り替える。
常にマウス中心へする場合は Follow Text Input Location をオフにする。
各区画内では枠を固定し、マウスはその中を移動する。画面端の区画はモニター端に一致する。

片方の辺だけ実画面が要求より小さい場合は、その辺を黒い余白で埋める。
両辺とも要求以下なら従来の全体表示となる。
切り出し有効時はSunshine内蔵の解像度自動変更・解像度リマップを抑止し、ホストの実解像度を保持する。
ユーザーが別途設定した外部コマンドによる解像度変更は対象外。

## 入力と低帯域モード

送信した範囲の原点を使って絶対マウス・タッチ・ペンの座標を変換する。
相対マウスはモニター全体を移動でき、区画をまたげる。絶対座標入力も、重なる範囲の切り替え境界を越えることで区画を移動できる。割り切れる辺に1区画追加するのは、端の絶対座標しか送れず隣へ入れなくなる問題への対策。
直接タッチ・ペンの接触中は追従を固定し、複数指はすべて離すまで固定する。
切断時に固定状態を解除する。
通常のMoonlightの映像・入力プロトコルを使用し、クライアントの改造は不要。
遅延した映像のフレーム番号は入力パケットに含まれないため、枠が移動中のクリックには遅延相当の誤差が残りうる。

鮮明領域・背景更新保持とは独立した設定。背景キャッシュは元モニターの座標で保持するため、
クロップを動かすたびに背景を全面初期化しない。低帯域モードの映像予算・FPS制御もそのまま適用する。
画面のパンは動画上の大きな変化になるため、通信量の減少を保証するものではない。

## 対応範囲

Windows D3D11変換（NVENC、D3D11経由AMF／Quick Sync等）。ソフトウェア変換は未対応で、
クロップを要求すると明示的なログエラーで接続を中止する。
[端中央でのモニター自動切り替え](monitor-switch.md)は、同じGPU・同じHDR状態・1接続で対応。画面をまたいだ連続合成は未対応。
各接続のクロップ枠は独立しているが、Windowsの実マウスと入力フォーカスは共有する。

iPad実機のタッチ／ペン動作はこのPCだけでは検証できない。

## 修正履歴

クロップのGPU定数は毎フレーム更新可能なD3D11_USAGE_DEFAULTで作成するよう修正した。
以前は不変バッファーを使っていたため、有効化ログとデコード成功だけでは映像の切り出しを確認できていなかった。
GPU回帰テストも本番と同じ生成関数を使用するよう変更した。
実解像度が要求以下の場合は `Viewport crop bypass ... reason=source_not_larger` を出力する。
PC側を手動で要求と同じサイズに変更した場合は、クロップせず全画面がそのまま配信される。
